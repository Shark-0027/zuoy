# FinGuard 界面与交互设计说明（DESIGN）

> 版本：0.2（本地实现版）  
> 日期：2026-10-26  
> 对应应用：`design_preview/index.html` + `src/finguard`  
> 运行方式：FastAPI 本地后端；可选远程模型叙述，无生产级登录  
> 注意：内置公司与样例数据为虚构；上传数据的来源与限制由证据链标注。

---

## 0. 实现更新（优先于历史静态描述）

- 页面已连接本地 FastAPI；指标、规则、证据、Agent 步骤和报告均为真实执行结果。
- 新增课堂投影模式和讲解模式；讲解模式读取当前计划、工具参数、证据和人工核验记录，不播放独立动画。
- 情景模拟改为服务端确定性计算，并返回敏感度矩阵、基准来源、固定假设与证据引用。
- 数据导入支持 CSV、XLSX 和基础文本型 PDF；支持人工字段映射与“确认保持未映射”。
- 报告由结构化状态生成 HTML 与 Markdown，页面和下载共享同一结果。
- 顶栏/侧栏会显示本地真实运行状态，而不是“静态设计预览”。

## 1. 设计目标

### 1.1 一句话

把 FinGuard 设计成 **一间安静的财务分析室**，而不是一个热闹的 AI 聊天窗口。

用户进入产品后，首先看到的是当前分析任务、异常信号、证据覆盖和下一步动作；Agent 的计划与工具调用被放进可展开的执行时间线，让“AI 做了什么、依据是什么、哪里需要人判断”一目了然。

### 1.2 三个设计支点

1. **Evidence before narrative（证据先于叙述）**  
   任何结论旁边都有规则、期间、数值、证据编号和限制。视觉上使用引用芯片、证据抽屉和核验状态，而不是大段 AI 口吻的结论卡片。

2. **A workspace, not a chatbot（工作台而非聊天框）**  
   主界面是任务、计划、时间线、表格和报告。没有输入框居中、气泡对话和“你好，我是财务助手”的模板。

3. **Calm authority（克制而可信）**  
   中性底色、墨色文字、少量深青强调色；风险色只用于风险；数字、表格和留白承担主要信息层级。没有装饰性渐变、无意义插画和循环动画。

### 1.3 面向的场景

- 桌面端 1366×768：信息密度足够，但不依赖悬停才能理解。
- 教室投影 1920×1080：标题、数字和状态能在 3–6 米距离辨认。
- 窄窗口：侧栏变为抽屉，双栏/三栏降为单栏，表格横向滚动。
- 教师演示：Agent 工作区可在一屏内解释“计划 → 工具 → 证据 → 核验”。

## 2. 视觉方向

### 2.1 关键词

Professional Financial SaaS · AI Agent Workspace · Evidence-based Analysis · Clean Dashboard · Interactive Financial Intelligence · Responsive Desktop Layout

### 2.2 气质

- 像成熟的 B2B 财务软件，而不是概念稿；
- 有编辑部式的排版秩序：粗体标题、细线分隔、克制的元信息；
- 数据是主角：指标数字最大，装饰最小；
- 状态语言清晰：正常、警告、异常、信息、不可计算各有稳定的呈现方式；
- 允许“未完成/待复核”出现在界面中，不假装一切都是绿色成功。

### 2.3 反模式（明确避免）

- 大面积蓝紫渐变、发光边框、玻璃拟态；
- 每个区域都做成独立大圆角卡片，造成“卡片汤”；
- 每个标题配一个彩色图标；
- 用聊天气泡承载分析过程；
- 为了让画面“有 AI 感”而加入持续旋转/脉冲动画；
- 所有按钮同一种视觉权重；
- 把风险等级只表示为颜色，不写文字；
- 使用在线字体、图标库或远程图片。

## 3. 色彩系统

颜色以 CSS 自定义属性定义在 `styles.css` 的 `:root`，界面组件只引用 token。

### 3.1 基础色

| 角色 | Token | 色值 | 用途 |
|---|---|---|---|
| 页面底色 | `--canvas` | `#F5F6F7` | 应用背景 |
| 主表面 | `--surface` | `#FFFFFF` | 卡片、表格、报告纸张 |
| 次表面 | `--surface-muted` | `#F8F9FA` | 表头、区块内部 |
| 墨色 | `--ink` | `#182230` | 标题、主要正文 |
| 次要文字 | `--ink-secondary` | `#475467` | 说明、表格内容 |
| 弱化文字 | `--ink-muted` | `#667085` | 元信息、轴标签 |
| 边框 | `--border` | `#E4E7EC` | 分隔线、输入框 |
| 强边框 | `--border-strong` | `#D0D5DD` | 表头下边线 |
| 侧栏 | `--navy` | `#0E1B26` | 深色导航 |
| 侧栏文字 | `--navy-ink` | `#C9D3DB` | 导航默认 |
| 品牌强调 | `--accent` | `#0F766E` | 主按钮、选中态、品牌标记 |
| 强调浅底 | `--accent-soft` | `#E6F4F1` | 标签、选中背景 |
| 强调深色 | `--accent-strong` | `#0B5F58` | 悬停、深色按钮 |

### 3.2 状态色

状态色使用深色前景 + 浅色背景组合，并始终配文字/图标。

| 状态 | 前景 | 背景 | 使用场景 |
|---|---|---|---|
| 正常 / 已验证 | `#067647` | `#ECFDF3` | 已完成、核验通过 |
| 警告 / 待复核 | `#B54708` | `#FFFAEB` | 需人工确认、数据警告 |
| 异常 / 高风险 | `#B42318` | `#FEF3F2` | 高风险异常、阻塞错误 |
| 信息 / 运行中 | `#175CD3` | `#EFF8FF` | 中性信息、链接 |
| 不可计算 / 未连接 | `#475467` | `#F2F4F7` | 缺失数据、未配置 |
| 模拟 / 未连接 | `#B54708` | `#FFF7E6` | 情景模拟或后端未连接提示，不使用绿色 |

### 3.3 图表色

图表使用经过校验的分类色板，与品牌深青分离，避免把 UI 色彩误读为数据语义。

| 角色 | 色值 | 用途 |
|---|---|---|
| 系列 1 | `#2A78D6` | 营业收入、模拟情景 |
| 系列 2 | `#EB6834` | 营业成本、对照情景 |
| 基线对比 | `#667085` | 基准情景的辅助参考 |
| 网格线 | `#E4E7EC` | 细实线，不使用虚线 |
| 轴文字 | `#667085` | 11–12px，等宽数字用于刻度 |
| 单序列趋势 | `#2A78D6` + 端点 | 单序列无需图例，标题说明指标 |

已验证：`#2A78D6` 与 `#EB6834` 在白色表面上的色盲分离、亮度、色度和对比度均通过校验。图表遵循单 Y 轴；收入与成本同量纲才同图，毛利率等不同量纲使用独立小图。

### 3.4 色彩使用规则

- 深青只代表品牌和交互，不代表“正常/安全”；
- 绿色只用于已核验、已完成；
- 黄色/橙色只用于需要人注意的模拟、警告或待复核；
- 红色只用于高风险或阻塞，不用于普通强调；
- 图表色不用于状态徽标，状态色不作为数据系列；
- 文字不使用系列色；身份由旁边色块/线标承担。

## 4. 字体与排版

### 4.1 字体栈

```css
font-family: "Inter", "SF Pro Text", "PingFang SC", "Hiragino Sans GB",
             "Noto Sans CJK SC", "Microsoft YaHei", sans-serif;
```

- 不加载外部字体，依赖系统字体回退；
- 中文正文字重 400/500，标题 600/700；
- 数字使用 `font-variant-numeric: tabular-nums`，保证表格对齐；
- 代码、公式、工具名使用：

```css
font-family: "SFMono-Regular", "Cascadia Code", "JetBrains Mono",
             "Consolas", "Liberation Mono", monospace;
```

### 4.2 字号层级

| token | 大小 | 用途 |
|---|---|---|
| `--text-xs` | 12px | 标签、图表轴、元信息（不用于长正文） |
| `--text-sm` | 13px | 表格、辅助说明、徽标 |
| `--text-base` | 14px | 正文、输入、导航 |
| `--text-md` | 16px | 卡片标题、关键正文 |
| `--text-lg` | 20px | 页面次级标题、报告章节 |
| `--text-xl` | 24px | 指标数值 |
| `--text-2xl` | 30px | 页面主标题 |
| `--text-hero` | 40px | 单个主视觉数字（工作台核心指标） |

### 4.3 行高与字距

- 正文行高 1.65；表格 1.5；标题 1.25；
- 大标题字距 -0.02em，英文品牌字距 -0.03em；
- 中文正文不使用大写变形；
- 金额数字使用 `¥1,284.0 万`，单位与数值分层显示。

## 5. 布局系统

### 5.1 应用骨架

```text
┌──────────────┬─────────────────────────────────────────────┐
│  Sidebar     │  Topbar: breadcrumb / demo badge / period   │
│  248px       ├─────────────────────────────────────────────┤
│  品牌        │                                             │
│  导航        │  Content: max-width 1560px, 32px gutter     │
│  状态        │  Page heading + sections + data             │
│  脚注        │                                             │
└──────────────┴─────────────────────────────────────────────┘
```

- 侧栏固定，内容区独立滚动；
- 侧栏展开 248px，收起 76px；
- 顶部栏高 64px，粘性定位；
- 内容最大宽度 1560px，左右至少 24px；
- 使用 8px 间距尺度：4, 8, 12, 16, 20, 24, 32, 40, 48；
- 卡片圆角 12px，按钮 8px，输入框 8px，小徽标 999px；
- 阴影极轻：`0 1px 2px rgba(16,24,40,.04)`；层级主要靠边框和留白。

### 5.2 栅格

- 工作台：12 列，主分析区 8 列 + 侧栏 4 列；
- 指标分析：图表 6/6，指标表全宽；
- Agent：左侧任务/计划 300–340px + 右侧时间线自适应；
- 报告：目录 210px + 正文自适应；
- ≤1180px：侧栏变为抽屉，主栅格可降为单列；
- ≤780px：所有双列变单列，表格横向滚动。

### 5.3 页面节奏

每个视图遵循同一结构：

1. 眉题（模块 + 运行编号）；
2. 页面标题（明确用户在做什么）；
3. 一句解释（产品的边界与当前上下文）；
4. 主操作（最多一个主按钮 + 一个次按钮）；
5. 上下文条（公司、期间、文件、状态）；
6. 数据/任务主体；
7. 脚注或限制提示。

## 6. 组件规范

### 6.1 导航

- 深色侧栏、浅色内容，形成清晰的工作空间；
- 分组：工作台 / 数据接入 / 智能分析 / 交付；
- 当前项：浅色高亮条 + 青色左边线 + 白色文字；
- 未读/数量徽标用低饱和背景，不使用红点堆叠；
- 收起后仅保留图标和工具提示（`title` + `aria-label`）。

### 6.2 按钮层级

| 类型 | 样式 | 用途 |
|---|---|---|
| Primary | 深青实底、白字 | 每个视图最多一个主操作 |
| Secondary | 白底、边框 | 查看、导出、辅助动作 |
| Ghost | 透明、悬停浅灰 | 表格行操作、工具栏 |
| Danger-ghost | 红色文字、透明底 | 删除等破坏动作（原型不出现破坏操作） |
| Link | 青/蓝文字 + 下划线 | 证据引用、页内跳转 |

按钮高度 36–40px，触控目标至少 36px；图标按钮 36×36px。禁用状态降低对比但保留可读标签。

### 6.3 卡片

卡片用于承载一组相关数据，不作为页面唯一结构。规范：

- 白底、1px 边框、12px 圆角、20–24px 内边距；
- 标题 15–16px / 600；说明 13px / 次要色；
- 头部右侧只放一个主要工具或状态；
- 同屏大卡片不超过 3–4 个；避免卡片内部再套“小卡片海”。

### 6.4 指标卡（Stat Tile）

```text
营业收入                         [同比 +8.6%]
¥12,840 万                       sparkline
2025 前三季度 · 示例数据
```

- 标题 13px 次要色；
- 数值 26–30px / 600，使用比例数字；
- 同比：方向 + 颜色 + 符号 + 文字，不只靠颜色；
- 迷你趋势线为单序列，低对比，端点用强调色；
- 底部标签至少显示期间或口径。

### 6.5 数据表

- 表头 12px / 500 / 大写间距；行高 44–52px；
- 数字列右对齐并使用 tabular-nums；
- 风险列使用带文字的徽标；
- 行悬停仅改变底色；可点击行有明确箭头或 cursor；
- 长表使用 `.table-wrap` 横向滚动，不压缩列宽；
- 关键行可加 3px 左侧状态线，但不使用整行高饱和底色。

### 6.6 状态徽标

结构：`[图标] 文字`。颜色 + 形状 + 文字三重编码。例：

- `● 已完成` 绿色；
- `▲ 待复核` 琥珀；
- `■ 高风险` 红色；
- `○ 未连接` 灰色；
- `◇ 模拟` 橙色描边。

### 6.7 证据引用芯片

```text
[E-03] 资产负债表 · 应收账款 · 2025-09
```

- 等宽编号，细边框，可点击；
- 悬停显示来源；
- 在报告中作为上标链接进入证据附录；
- 颜色不能替代来源文字。

### 6.8 时间线

- 左侧 24px 垂直轴：完成圆点、待复核方块、未执行空心点；
- 轴线上方为步骤标题、状态、耗时；
- 摘要行显示工具、结果、引用；
- 展开区使用浅色分区，不嵌套卡片；
- 默认展开 1–2 个关键步骤，其余收起；
- “全部展开/收起”放在时间线头部；
- 不使用自动轮播或模拟进度条。

### 6.9 抽屉

- 右侧滑入，宽度 `min(560px, 100vw)`；
- 顶部固定标题 + 关闭；主体滚动；底部固定动作；
- 背景遮罩 `rgba(16,24,40,.45)`；
- 支持 Esc、点击遮罩关闭；
- 打开时焦点进入抽屉，关闭后返回触发按钮；
- 不超出视口，移动端占满宽。

### 6.10 图表

- 形式先于颜色：收入用柱，毛利率用线，情景对比用成对柱；
- 单序列不加图例；双序列必须有图例 + 直接标签；
- 柱宽 ≤24px，数据端 4px 圆角，基线端方角；
- 线宽 2px，端点 ≥8px 并带 2px 表面色描边；
- 网格为 1px 实线，弱于数据；
- 悬停有 tooltip；键盘可聚焦数据点；
- 每个图表提供数据表开关和替代文本；
- 不使用双 Y 轴；不同量纲拆成小图。

## 7. 页面设计

### 7.1 工作台（Dashboard）

**目的**：回答“当前最值得看什么、分析做到哪里、下一步做什么”。

结构：

1. 页面标题 + 新建分析；
2. 公司/期间/文件/时间上下文条；
3. 四个核心指标：收入、毛利率、净利润、经营现金流；
4. 当前分析任务（目标、进度、证据数、工具数、进入工作区）；
5. 异常雷达（高风险/中风险/待补证数量、最近异常）；
6. 营收与毛利率小倍数趋势图；
7. 最近分析任务表。

视觉层级：页面标题 < 当前任务 < 指标数值 < 异常风险。工作台不放聊天输入框。

### 7.2 数据导入（Import）

**目的**：建立可信的数据底座。

结构：

1. 四步进度：上传 → 字段映射 → 质量检查 → 开始分析；
2. 左侧拖放区 + 文件队列；右侧质量总览；
3. 字段映射表（含一个模糊匹配需要确认）；
4. 数据质量检查项（阻塞/警告/提示）；
5. 原始数据预览标签页（利润表/资产负债表/现金流量表/费用明细）；
6. 底部“进入 Agent 工作区”动作，并明确原型不执行真实分析。

关键状态：

- 未选择文件：空状态与支持格式；
- 已选择文件：文件名、大小、状态；
- 解析失败：红色错误 + 重试；
- 字段模糊：黄色“需确认” + 下拉选择；
- 缺失值：单元格浅红底 + 图例；
- 不可计算：灰色状态 + 原因，而不是 0。

### 7.3 Agent 工作区（Agent Workspace）

**目的**：让老师/用户看懂 Agent 如何工作，同时不把它伪装成聊天机器人。

布局：

- 顶部：任务名、示例任务切换、目标摘要、运行模式；
- 左栏：分析目标、约束、任务计划（8 步）、工具调用记录；
- 右栏：执行时间线（主要视觉），待核验问题、结论草稿、证据覆盖；
- 顶部声明区分“真实后端执行”和“未连接后端”；不播放独立模拟状态。

时间线步骤：

1. 检查数据完整性；
2. 计算核心指标；
3. 执行跨期比较；
4. 检测异常候选；
5. 核验异常证据；
6. 形成原因假设；
7. 运行经营情景模拟；
8. 生成报告草稿并核验。

状态：`已完成` / `需复核` / `待执行` / `跳过` / `失败`。每个状态有文字和符号。

重点设计：

- 步骤 05 展示“12/16 条证据已定位，4 条需要补充资料”；
- 步骤 06 显示 Agent 暂停原因，不强行给出结论；
- 步骤 08 显示“草稿已生成，等待人工复核”，不声称已交付；
- 工具调用显示“模拟调用”标签；
- 结论草稿分三块：已验证、待核验、不能断言。

### 7.4 指标分析（Metrics）

**目的**：解释数字如何算出来、变化在哪里。

结构：

1. 期间与导出控制；
2. 六项指标摘要；
3. 营业收入与营业成本对比图（同量纲双序列）；
4. 毛利率趋势小图（单序列）；
5. 指标明细表：本期、上期、变化、公式、状态；
6. 不可计算状态示例（存货周转天数缺少平均存货）；
7. 数据表视图。

强调“口径”而非只看涨跌：毛利率下降 2.7pp 与成本增速 13.0% 并列展示。

### 7.5 异常诊断（Anomalies）

**目的**：从“发现异常”走到“知道该核查什么”。

结构：

1. 风险摘要（高/中/低/待补证）；
2. 筛选器（全部/高/中/低）；
3. 异常表：标题/编号、风险、规则、关键指标、期间、证据摘要、查看；
4. 详情抽屉：
   - 标题与等级；
   - 触发规则与阈值；
   - 实际指标 vs 基线；
   - 原始数据行；
   - 计算公式；
   - 判断依据；
   - 结论限制；
   - 后续核查建议。

文案原则：每条异常都明确“不构成舞弊或违法结论”。

### 7.6 情景模拟（Scenario）

**目的**：用透明参数支持经营讨论，而不是给出“AI 预测”。

布局：

- 左侧参数面板：三个滑块 + 数值输入 + 预设；
- 右侧结果：基准 vs 模拟、净利润、净利率、变化额、变化率；
- 下方：对比柱图、敏感度矩阵、假设与限制；
- 顶部/底部双重“模拟，不是预测”标识；结果来自服务端确定性函数。

交互：

- 滑块改变时即时计算；
- 结果数字和条形宽度同步；
- “重置为基准”恢复 0/0/0；
- 参数变化不会触发网络请求；
- 报告中的情景快照显示参数和“模拟”状态。

### 7.7 报告（Report）

**目的**：交付一份能讨论、能追溯、能保留边界的结构化材料。

布局：

- 报告头部：公司、期间、版本、草稿状态、复制/下载/打印；
- 左目录：执行摘要、数据质量、核心指标、异常发现、证据与计算、情景模拟、建议、限制；
- 正文：报告纸张式排版，章节编号和引用芯片；
- 标签页：报告正文 / 证据附录；
- 侧栏（可选）：核验状态与证据覆盖。

报告不是“AI 总结”页面：每个结论后跟证据引用，每个模拟段落带参数，最后一段永远是分析限制。

### 7.8 设置（Settings）

**目的**：诚实展示系统边界和后续连接计划。

结构：

1. 运行状态表：静态预览、模型未配置、Agent 未启动、登录为本地访客、后端未启动；
2. 数据安全原则；
3. 规划中的连接配置（禁用/占位，不显示密钥）；
4. 设计阶段限制；
5. 版本与文档链接。

绝不显示伪造的“已连接”绿色状态。连接测试按钮只提示“原型不会发起网络请求”。

 ├─ 新建分析 → 数据导入 → Agent 工作区 → 报告

## 9. 主要交互流程

### 9.1 从工作台开始分析

```text
工作台
  → 点击“新建分析”
  → 数据导入（显示示例文件队列）
  → 确认模糊字段映射
  → 查看数据质量
  → 点击“进入 Agent 工作区（原型）”
  → 显示模拟计划与时间线
  → 打开异常详情
  → 运行情景模拟
  → 打开报告草稿
```

原型中的每一步是界面状态切换，**没有** 后台任务、轮询或定时器。

### 9.2 复核异常

```text
异常诊断
  → 筛选“高风险”
  → 点击行
  → 抽屉打开，焦点进入
  → 查看原始数据/公式/依据/限制
  → Esc 或关闭返回原行
```

### 9.3 情景参数更新

```text
拖动营收变化率
  → 前端读取三个参数
  → 使用确定性公式计算
  → 更新结果数字、变化百分比、对比柱、敏感度矩阵
  → 显示“模拟”标签
```

不使用 LLM 计算，不使用延时制造“思考中”。

### 9.4 报告交付

```text
报告
  → 切换到证据附录
  → 展开证据
  → 复制执行摘要（前端剪贴板）
  → 下载由后端生成的结构化 Markdown
  → 打印/保存 PDF（浏览器打印）
```

所有动作提供即时 toast 反馈；失败时回退到文本选择。

## 10. 前端到本地后端的连接方式（已实现）

### 10.1 保留的设计契约

前端契约不是一次性 mock。它定义了：

- 视图与路由命名；
- 卡片/表格/时间线的字段；
- 状态枚举与视觉映射；
- 证据引用和工具运行 ID 的展示位置；
- 情景参数和结果的字段名；
- 空态、错误态与加载态的位置。

### 10.2 未来数据接入点

| 原型区域 | 正式版数据源 |
|---|---|
| 公司/期间上下文 | `GET /api/workspaces/{id}` |
| 文件队列 | `POST /api/uploads` |
| 字段映射 | `GET /api/uploads/{id}/mapping`、`PATCH .../mapping` |
| 质量检查 | `GET /api/uploads/{id}/quality` |
| 当前分析 | `GET /api/analyses/{id}` |
| Agent 计划/时间线 | `GET /api/analyses/{id}/events` 或 SSE |
| 指标 | `GET /api/analyses/{id}/metrics` |
| 异常 | `GET /api/analyses/{id}/findings` |
| 情景模拟 | `POST /api/analyses/{id}/scenario` |
| 报告 | `GET /api/analyses/{id}/report` |
| 系统状态 | `GET /api/health`、`GET /api/config/status` |

### 10.3 交互替换策略

- 静态数组 → API 响应；
- 前端情景计算 → 服务端确定性计算（前端保留即时预览）；
- 静态时间线 → Agent 事件流；
- 静态报告 → 服务端报告版本；
- toast 反馈 → 请求状态 + 错误处理；
- 本地访客 → Supabase Auth 会话；
- 本地运行标识 → 真实环境标识 + 数据来源/时间。

### 10.4 不可改变的原则

即使接入真实后端，也必须保留：

- 数字可追溯；
- 结论与证据分离；
- 模拟与事实分离；
- 待复核状态显性；
- 报告限制章节；
- 前端不接触模型密钥。

## 14. 设计决策记录（ADR 摘要）

### ADR-01 为什么不用聊天布局

聊天布局会把分析过程压缩成“用户问 → AI 答”，无法表达计划、工具、状态和证据关系。FinGuard 的核心是任务工作区，聊天只适合作为后续“追问”辅助，不应成为主界面。

### ADR-02 为什么把“待复核”放在主视觉

财务分析的可信度来自知道哪里还不能确认。把待复核、缺失证据和限制放在高可见位置，比全部显示“完成/成功”更专业，也更符合教学目的。

### ADR-03 为什么使用深色侧栏 + 浅色内容

深色侧栏建立稳定的工作空间边界，浅色内容区提升表格和报告的可读性；同时避免全深色界面在教室投影中产生反光与对比问题。

### ADR-04 为什么图表用蓝/橙而不是品牌青

品牌青在 UI 中承担交互语义；图表需要独立的、经校验的分类色，避免用户把“青色数据”误解为“正常/推荐”。蓝橙在色盲与对比度上通过校验。

### ADR-05 为什么情景模拟用确定性公式

场景参数与利润表之间的关系必须透明、可复核、可测试。让 LLM 直接生成数字会破坏可追溯性；LLM 只负责解释假设和结果。

### ADR-06 为什么当前实现不使用前端计时器伪造执行

本地版本通过 `POST /api/analyses/{id}/advance` 逐步执行真实 Python 工具。页面上的每次状态变化都来自后端返回的步骤状态、实际耗时和工具结果；前端的短间隔只用于课堂可读性，不改变执行事实。

### ADR-07 为什么“讲解模式”读取真实记录

讲解模式不是另一套演示脚本。它从当前分析状态读取计划、工具、证据、暂停问题和结论，随真实分析变化；没有报告时第五阶段会明确显示“尚未生成”。

## 18. LLM 解读界面（已实现）

### 18.1 位置与职责
- Agent 页面在「待核验问题 / 结论草稿」下方增加「AI 解读」卡片。
- 模型只接收指标方向、规则状态、限制与待核验事项；不接收原始文件或逐行科目。
- 输出固定为 `summary / signals / questions / limitations`，前端分栏展示。

### 18.2 校验与降级
- 响应必须可解析为 JSON；非法 JSON 拒绝。
- 输出中包含数字时拒绝，避免模型引入未经验证的金额或比率。
- 输出中包含舞弊、造假、违法行为、投资建议、审计意见等定性短语时拒绝。
- 调用失败、超时或校验失败时，卡片显示真实错误；Agent 计算和报告不受影响。
- 模型状态在卡片、顶栏与 Agent 摘要中区分“未配置 / 可生成 / 已生成 / 模型回退”。

### 18.3 连接测试
- 设置页提供「测试模型」按钮。
- 测试请求只发送 `OK` 指令，不发送任何财务数据。
- 成功时显示模型与延迟；失败时显示脱敏后的错误。
- 401/403、404、429、5xx 分别映射为认证、路径、限流/配额和服务问题；默认不信任 shell/system 代理。
